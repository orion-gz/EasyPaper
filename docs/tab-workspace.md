# 탭 워크스페이스

`ask/UI/renew.png`의 고정 사이드바, 상단 탭, 문서 목차, 본문, 우측 도구 패널 구성을 적용한다.

## 화면 구성

- 사이드바에서 Dashboard, Library, AI Chats, Notes, Reading History, Research Graph를 열면 페이지별 탭 하나를 생성하거나 기존 탭을 활성화한다. Settings는 모달로 유지한다.
- 문서는 ID별로 탭 하나를 사용한다. 탭 닫기, 드래그 순서 변경, 전체 탭 선택, 새 탭의 문서 열기·추가 메뉴를 제공한다.
- 탭에서 방향키/Home/End로 이동, Delete로 닫기, Alt+방향키로 순서를 변경한다.
- 문서 왼쪽은 Outline/Thumbnails, 중앙은 원문·번역·병렬 읽기, 오른쪽은 AI Chat/Notes/Annotations로 구성한다. 병렬 읽기는 양쪽 패널을 접고, 종료하면 이전 패널 상태를 복원한다.
- 하단 도구는 텍스트 선택, 손 도구, 페이지 이동, 확대·축소, Focus, 전체 화면, 페이지 폭 맞춤을 제공한다. 좁은 화면에서는 목차와 AI 패널을 겹쳐 표시하고 동시에 하나만 연다.

## 상태와 수명

`workspaceTabsStore.js`는 탭 순서, 활성 탭, 문서 제목, 읽기 위치·배율·패널 설정을 관리한다. 저장 키는 서버 origin, 사용자, 연구/일반 모드로 구분한다. 채팅 내용, 입력 초안, 스트림, PDF 데이터는 탭 복원 저장소에 기록하지 않는다.

`workspaceTabs.js`가 화면 셸과 페이지 탐색을 소유한다. 페이지의 스크롤을 유지하고, Library/Notes/History/Dashboard/AI Chats는 재진입 시 데이터를 다시 읽는다. Library 검색·필터·선택 및 AI Chats 보기 설정을 유지한다. 기존 URL 해시와 브라우저 뒤로/앞으로 이동을 지원한다.

각 문서는 동일 출처 iframe에서 기존 뷰어를 실행한다. 기존 뷰어의 DOM ID, PDF worker, 모듈 상태, 채팅·번역 요청을 문서별로 격리한다. `documentWorkspaceRuntime.js`의 런타임과 부모 셸은 제한된 메서드와 출처·발신 창을 검증하는 메시지로 통신한다.

- 탭 전환 전에 읽기 위치를 저장한다. 주석·메모는 기존 로컬 저장소와 동기화 큐에 먼저 기록하며, 서버 동기화는 백그라운드에서 재시도한다. 서버 동기화 지연만으로 탭 전환·닫기를 차단하지 않는다.
- 비활성 문서는 읽기 시간을 누적하지 않고 PDF 캔버스·관찰자·썸네일 렌더링을 해제한다. 다시 활성화하면 읽기 위치에서 렌더링을 재개한다.
- 탭을 바꾸거나 닫아도 진행 중인 채팅·번역은 원래 문서에서 계속된다. 닫힌 문서의 런타임은 요청이 끝나면 제거한다. 열린 비활성 탭은 작업 상태를 표시한다.
- 재시작 후에는 탭 메타데이터를 복원하고 활성 문서부터 지연 로드한다. 문서 접근 권한이 없거나 삭제되었다면 해당 탭을 제거한다. 일시적인 로드 실패는 재시도를 제공한다.
- UI 배율은 문서 안에서 적용하고 iframe 외곽은 화면 좌표를 유지한다. 테마·언어·배율 변경을 문서 런타임에 전달한다.

## CSP

웹 서버와 데스크톱 CSP의 `frame-ancestors`를 `'self'`로 설정한다. 내부 문서 런타임을 허용하기 위한 명시적으로 승인된 변경이며 외부 출처에서 앱을 임베딩하는 것은 허용하지 않는다.

## 검증과 한계

탭 저장소 단위 테스트와 `workspace-tabs.spec.js`에서 복원, 중복 방지, 문서별 초안, 페이지 탭, 키보드 탐색, 패널, 요청 중 닫기, 캔버스 해제, 로드 실패 처리를 다룬다. 기존 뷰어 회귀 테스트는 `activeReader`/`evaluateReader`를 통해 활성 문서를 대상으로 실행한다.

비활성 문서의 캔버스는 해제하지만 PDF 문서 핸들과 모듈은 탭을 닫을 때까지 유지한다. 많은 문서를 열면 메모리 사용량이 증가할 수 있다. 진행 중인 요청은 앱 전체 종료 후에는 이어지지 않는다. 탭 복원은 현재 기기의 브라우저 저장소를 사용한다.

## 읽기 도구 보완

- 새 문서는 페이지 폭 맞춤으로 연다. 가장 넓은 페이지와 뷰어의 실제 여백을 기준으로 배율을 계산하고, 패널·창 크기가 바뀌면 다시 맞춘다. 직접 확대·축소하면 수동 배율로 전환한다. 폭 맞춤 여부도 문서별로 복원하며, 기존 저장 상태의 수동 배율은 유지한다.
- 검색 버튼과 Ctrl/Cmd+F로 문서 검색을 연다. PDF의 미렌더링 페이지와 기존 복구 텍스트도 검색한다. Enter/Shift+Enter 또는 화살표로 결과를 이동하고, 지원 브라우저에서는 본문 결과를 강조한다. 검색 결과 문맥은 검색창에도 표시한다. Escape로 닫는다.
- 검색은 문서별로 격리된다. 입력 변경·닫기·탭 비활성화 시 이전 검색을 취소하고, 복귀 시 필요한 검색을 재개한다. 최대 10,000개 결과를 유지하며 제한에 도달하면 ≥ 표기로 알린다.
- 손 도구는 드래그로 본문을 이동한다. 텍스트 선택 도구로 돌아가면 기존 선택·주석 동작을 사용한다.
- 우측 도구 패널은 독립된 카드로 표시한다. Notes/Annotations는 로컬 변경, 서버 동기화, 다른 동일 출처 창의 저장 변경을 반영한다.
- 수동 번역 오류와 전체 번역 작업의 실패 상태를 탭 오류 표시와 연결한다.
- 자동 폭 맞춤·배율 변경 후에도 번역 지연 로딩과 읽기 통계 콜백을 유지한다.
- 자동 폭 맞춤·배율 변경 시 읽던 페이지와 페이지 내 위치를 유지한다. 텍스트 선택이나 메모 편집 중에는 자동 PDF 재렌더링을 피한다.
- 주석 툴팁과 선택 메뉴는 UI 배율을 반영해 선택 영역 밖에 배치한다. 인용 조회 팝업을 조작한 뒤에는 응답에 따른 위치 변경만으로 닫히지 않으며 바깥 클릭·스크롤·Escape로 닫는다.
- 메모 생성과 페이지 hover에서 위치를 움직이는 애니메이션을 제거하여 선택·키보드 이동 좌표를 안정적으로 유지한다.
- 본문 스크롤 영역은 키보드로 접근할 수 있다. 좁아진 탭 표시줄에서도 활성 탭을 화면 안으로 이동시킨다.
- 웹의 `/index.html` 직접 접근에도 SPA 진입 경로와 동일한 CSP 및 캐시 정책을 적용한다.

## 검증 범위 구분

자동 브라우저 테스트는 실제 PDF 렌더러와 브라우저를 사용하지만 API는 결정적인 응답으로 모킹한다. AI·번역의 전환/닫기 중 요청 유지, 오류 재시도, 오프라인 큐 보존, 모드별 탭 복원, 키보드 순서 변경과 브라우저 이력, 전체 문서 검색을 검증한다. CSP 테스트는 운영 설정의 정책 문자열을 브라우저에 적용하여 동일/다른 출처 임베딩을 검사하고, Python 테스트는 웹 응답 헤더를 검사한다.

12개 문서 시나리오는 활성 문서만 PDF 캔버스를 유지하고 닫은 런타임이 제거되는지 확인하며 Chromium 실행에서는 JS heap 측정 자료를 첨부한다. 작은 테스트 PDF를 사용하므로 대용량 실문서의 성능 보장은 아니다. 실제 외부 AI 공급자와 네이티브 Tauri 앱의 통합 동작은 별도 환경 검증이 필요하다.

## 최종 로컬 검증 (2026-09-26)

- 프로덕션 빌드 및 i18n 검증 통과. 기존 대형 번들 경고는 남아 있다.
- 프런트엔드 단위 테스트: 152개 통과.
- Chromium 전체 E2E: 225개 통과, 비공개 PDF fixture가 필요한 기존 4개 건너뜀.
- WebKit: 탭 작업 영역·CSP·읽기 위치·UI 배율·메모·인용 41개와 실제 텍스트 드래그 선택 1개를 검증했다. 초기 실패를 수정한 후 관련 묶음을 재실행하여 총 42개 고유 시나리오의 통과를 확인했다.
- 백엔드 CSP 테스트: 3개 통과.
- 메모 키보드 이동, 텍스트 선택, 인용 팝업 회귀는 반복 실행으로도 확인했다. 메모 검사는 폭 맞춤과 텍스트 레이어 준비 후 측정하며, 실행 취소는 각 브라우저의 일반 입력창과 비교한다.
- macOS WebKit CI에 작업 영역·CSP·메모·인용·읽기 위치·UI 배율 회귀를 추가했다. 로컬 WebKit 결과는 네이티브 Tauri 실행 검증을 대신하지 않는다.
