# HTTP(S), SSH 및 여러 추론 서버 연결

[English documentation](ssh-connections.md) · [랩 모드 설치 및 연결](lab-mode.ko.md) · [데스크톱 원격 서버 연결](desktop-remote-server.md)

## 추론 서버 등록 및 모델 선택

관리자는 **설정 → 랩 모드**에서 Ollama 또는 vLLM 서버를 여러 개 등록할 수 있습니다. 서버마다 허용 모델을 지정하고 전체 기본 서버를 선택합니다. vLLM 서비스 URL에는 `/v1`을 포함합니다.

1. HTTP(S) 또는 SSH를 선택하고 서비스 주소를 입력합니다.
2. 모델 이름을 모르면 모델 목록을 비운 상태에서 서버를 저장한 뒤 연결을 확인해 제공 모델을 조회합니다.
3. 허용 모델과 기본 모델을 지정하고 다시 연결을 확인합니다. 기본 모델이 있으면 짧은 추론 요청도 실행하며, vLLM은 같은 연결을 통해 `cache_salt` 지원 여부를 확인합니다.
4. 구성원은 개인 설정에서 사용할 서버와 모델을 선택합니다.

개인 모드에서도 같은 서버 목록을 사용할 수 있습니다. 개인 설정에서 서버와 모델을 선택해 저장하면 적용되며, 기존 개인 모델 설정을 사용하는 옵션으로 되돌릴 수 있습니다. 개인 모드와 랩 모드의 선택은 각각 보관됩니다. 요청은 선택한 서버로 전송되며 자동 분산이나 장애 시 전환은 제공되지 않습니다. 추론을 처리 중인 서버는 수정하거나 삭제할 수 없습니다.

## SSH로 연결

1. SSH 호스트, 포트(기본값 22), 사용자 이름을 입력합니다.
2. 비밀번호 또는 OpenSSH/PEM 형식의 개인 키를 입력합니다. 암호화된 키를 사용한다면 키 암호를 입력합니다.
3. **SSH 서버에서 접근할 수 있는 서비스 URL**을 입력합니다. Ollama와 SSH가 같은 서버에서 실행 중이면 예를 들어 `http://127.0.0.1:11434`를 사용합니다.
4. 표시된 호스트 키 지문을 서버 관리자에게 확인한 뒤 승인합니다. 서버 키가 바뀌면 새 지문을 다시 확인합니다.

EasyPaper 백엔드는 필요한 시점에 루프백 포트로 터널을 열고, 연결이 끊기면 다음 요청에서 재연결합니다. 중단된 추론 요청은 터널에서 자동으로 재실행되지 않습니다. 터널 안에서 HTTPS를 사용해도 인증서 검증과 원래 TLS 서버 이름은 유지됩니다.

데스크톱 앱에서 EasyPaper 자체에 SSH로 접속할 때는 **설정 → 데이터 → 서버 연결**에서 SSH를 선택합니다. 서비스 URL에는 SSH 서버에서 보이는 EasyPaper 주소(예: `http://127.0.0.1:8000`)를 지정한 뒤 EasyPaper 계정으로 로그인합니다. 로그인 세션과 동기화는 SSH 호스트, 계정 및 서비스 URL별로 분리됩니다. 동기화와 오프라인 계정 확인도 같은 터널을 사용합니다.

브라우저로 EasyPaper를 처음 열 때는 HTTP(S) 주소 또는 터미널에서 미리 연 SSH 터널을 사용합니다. 원격 EasyPaper에 등록한 추론 서버용 SSH 터널은 원격 EasyPaper의 백엔드가 엽니다. [터미널에서 SSH 터널 열기](lab-mode.ko.md#ssh-터널)

## 접속 정보 저장

저장 옵션을 켜면 재시작 후에도 접속 정보를 사용할 수 있습니다. 저장 옵션이 꺼져 있으면 접속 정보는 현재 백엔드 프로세스의 메모리에만 유지됩니다. 편집 화면에서 비밀 입력란을 비워 두면 기존 값이 유지됩니다. 저장 옵션을 끄면 영구 저장된 값이 삭제되며, 서버를 삭제하면 그 서버의 저장된 자격 증명도 삭제됩니다.

데스크톱에서는 macOS 키체인, Windows Credential Locker 또는 Linux Secret Service가 필요합니다. 웹 배포에서 영구 저장을 사용하려면 백엔드 환경에서 Fernet 키를 생성하고 배포 환경의 비밀 관리 기능으로 `EASYPAPER_CONNECTION_KEY`에 전달합니다.

```sh
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

키는 데이터베이스 및 백업과 별도로 보관하고 재시작 후에도 같은 값을 사용합니다. 암호화된 기록은 앱 설정 디렉터리의 `connection-secrets`에 저장됩니다. Docker에서는 `/data/connection-secrets`를 사용하므로 컨테이너를 교체할 때 `/data` 볼륨과 키를 보존합니다. 키를 변경하면 접속 정보를 다시 입력해야 합니다. 웹에서 접속 정보를 입력할 때는 신뢰할 수 있는 연결을 사용합니다.

기존 단일 서버 설정은 기본 서버 하나로 이전됩니다. 이전 설정의 API 키는 해당 서버를 명시적으로 저장할 때 선택한 저장 방식으로 옮겨집니다. 연결 설정과 호스트 확인은 관리자에게만 허용되며 구성원은 서버 이름과 허용 모델을 볼 수 있습니다. API와 마이그레이션 세부 사항은 [영문 SSH 연결 문서](ssh-connections.md#apis)를 참고합니다.
